1. Tổng quan — đơn đi qua những trạng thái nào

Khách quét mã QR tại bàn, xem thực đơn trên điện thoại và tự đặt món. Nhân viên tư vấn (Sale) nhìn thấy đơn ngay trong khung chat, trao đổi với khách, rồi xác nhận. Phần mềm tính tiền của bạn nhận đơn ở bước xác nhận, không phải lúc khách bấm đặt.

Khách chọn món  ──▶  order.created      đơn mới, CHƯA trừ kho, chờ Sale
      │
      │ (khách sửa đơn)
      ├──────────────▶  order.updated      đơn đổi nội dung
      │
Sale xác nhận  ────▶  order.confirmed    ĐÃ trừ kho, bếp làm, bill tạm tính gửi khách
      │
Khách chọn cách trả ▶  payment.selected   khách bấm, HOẶC hệ thống tự chọn sau 2 phút
      │
Nhân viên thu tiền ─▶  order.paid         tiền đã vào

Mốc quan trọng nhất là order.confirmed. Trước mốc đó đơn chỉ là đề nghị của khách, có thể thay đổi hoặc bị từ chối. Từ mốc đó trở đi tồn kho đã bị trừ và bếp đã bắt đầu làm.

Nếu phần mềm của bạn chỉ muốn nhận một sự kiện duy nhất, hãy chọn order.confirmed.

2. Hai chiều tích hợp: đẩy và đọc về

ChiềuCách hoạt độngKhi nào dùng
Đẩy (webhook) Pastie gọi POST tới URL của bạn mỗi khi có sự kiện. Mặc định. Nhận đơn theo thời gian thực.
Đọc về (pull) Bạn gọi GET /api/pos/v1/orders để lấy danh sách đơn. Đối soát cuối ca, hoặc bù lại các webhook đã lỡ khi máy chủ bạn tạm ngừng.

Nên dùng cả hai. Webhook cho tốc độ, đọc về cho chắc chắn. Chỉ dựa vào webhook thì một lần máy chủ bạn khởi động lại là mất đơn mà không ai biết.

Nếu bạn không khai URL webhook, hệ thống vẫn ghi nhận đầy đủ mọi sự kiện và bạn lấy về bằng API đọc. Không mất dữ liệu.

3. Khoá và cách lấy

Chủ cơ sở (Agent) vào console Pastie, mở Thực đơn → Kết nối phần mềm tính tiền, khai URL webhook và bấm lưu. Hệ thống sinh ra hai khoá:

KhoáTiền tốDùng để
api_keypst_pos_… Gọi API đọc về. Gửi trong header X-Pastie-API-Key.
signing_secretpst_whsec_… Xác minh chữ ký webhook. Không bao giờ gửi khoá này đi đâu.

Hai khoá chỉ hiện đúng một lần ngay sau khi tạo. Console về sau chỉ hiển thị 6 ký tự cuối của api_key để đối chiếu. Mất khoá thì phải tạo lại, và bản cũ ngừng hoạt động ngay.

4. Webhook: header, chữ ký, cách xác minh

Pastie gửi POST với Content-Type: application/json tới URL bạn khai.

Header

HeaderVí dụÝ nghĩa
X-Pastie-Eventorder.confirmed Tên sự kiện. Trùng với trường event trong thân.
X-Pastie-Delivery1482 Mã lần gửi. Dùng khi cần đối chiếu với chúng tôi.
X-Pastie-Signaturesha256=a3f1… Chữ ký HMAC-SHA256 của toàn bộ thân request, khoá là signing_secret.

Cách xác minh

Tính HMAC-SHA256 trên chuỗi thân thô (raw body) — không phải trên JSON đã parse rồi stringify lại, vì thứ tự khoá và khoảng trắng có thể khác đi và chữ ký sẽ không khớp.

signature = "sha256=" + HMAC_SHA256(raw_body, signing_secret).hex()

So sánh bằng hàm so sánh thời gian hằng định (hash_equals trong PHP, crypto.timingSafeEqual trong Node) chứ không dùng ==.

Bạn cần trả về gì

Trả HTTP 2xx khi đã nhận được. Bất kỳ mã nào khác được coi là thất bại và sẽ được gửi lại. Nên trả lời nhanh (dưới 8 giây) rồi xử lý nền — quá 8 giây là timeout và bị tính là thất bại.

5. Chống trùng lặp và cơ chế thử lại

Mỗi sự kiện có event_id theo dạng:

<order_id>:<event>:v<version>
ví dụ:  9f3c1a2b-…:order.confirmed:v1

Hãy lưu event_id và bỏ qua nếu đã xử lý. Đây là cách duy nhất bảo đảm không tạo hai đơn cho cùng một sự kiện khi mạng chập chờn.

Trường version tăng lên mỗi khi đơn thay đổi nội dung. Nếu bạn nhận được version nhỏ hơn bản đã lưu, đó là gói đến muộn — bỏ qua, đừng ghi đè.

Pastie thử lại tối đa 5 lần cho mỗi sự kiện thất bại, giãn cách tăng dần. Sau đó sự kiện được đánh dấu thất bại và bạn lấy về bằng API đọc.

auto_selected: true — đây là đồng ý ngầm, không phải một cú bấm.

Sau khi bill tạm tính gửi đi, khách được báo trước rằng nếu không chọn gì trong 2 phút thì hệ thống sẽ tự chọn phương thức trả chậm mà cơ sở đã cấu hình (room_charge hoặc pay_later). Hết 2 phút mà khách im lặng thì phương thức đó được ghi nhận với auto_selected: true.

Nếu phần mềm của bạn có quy trình đối soát hay tranh chấp, nên phân biệt hai trường hợp này: khách chủ động bấm, và khách không phản hồi.

9. API đọc về

Gửi khoá trong header X-Pastie-API-Key. Không dùng query string — khoá lọt vào log máy chủ.

GET/api/pos/v1/orders

Danh sách đơn của cơ sở, mới nhất trước.

Tham sốKiểuMặc địnhGiải thích
updated_afterISO-8601— Chỉ lấy đơn sửa sau mốc này. Dùng để đối soát tăng dần.
limitint 1–10050Số đơn mỗi lần.
curl -H "X-Pastie-API-Key: pst_pos_xxxxx" \
  "https://api.pastiechat.com/api/pos/v1/orders?updated_after=2026-09-02T00:00:00Z&limit=50"
{
  "data": [ { …cùng cấu trúc như webhook… } ],
  "count": 50,

has_more: true nghĩa là còn đơn nữa. Lấy updated_at lớn nhất trong data làm updated_after cho lần gọi kế tiếp.

Một đơn cụ thể. Trả về cùng cấu trúc, với event: "order.snapshot".

10. Mã mẫu

Node.js (Express)

const express = require('express');
const crypto = require('crypto');
const app = express();

// QUAN TRỌNG: lấy raw body, vì chữ ký tính trên chuỗi thô.
app.post('/pastie/webhook',
  express.raw({ type: 'application/json' }),
  (req, res) => {
    const secret = process.env.PASTIE_SIGNING_SECRET;
    const expected = 'sha256=' + crypto.createHmac('sha256', secret)
      .update(req.body).digest('hex');
    const got = req.get('X-Pastie-Signature') || '';

    if (got.length !== expected.length ||
        !crypto.timingSafeEqual(Buffer.from(got), Buffer.from(expected))) {
      return res.status(401).end();
    }

    const payload = JSON.parse(req.body.toString('utf8'));

    if (daXuLy(payload.event_id)) return res.status(200).end();  // chống trùng
    luuLai(payload.event_id);

    if (payload.event === 'order.confirmed') {
      inPhieuBep(payload.order, payload.chat.qr_label);
    }

    res.status(200).end();   // trả nhanh, xử lý nặng để nền
  });

PHP

<?php
$raw    = file_get_contents('php://input');
$secret = getenv('PASTIE_SIGNING_SECRET');

if (!hash_equals($expected, $got)) {
    http_response_code(401);
